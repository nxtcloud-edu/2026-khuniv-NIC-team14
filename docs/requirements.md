# 뉴스레슨 (News Lesson) — 요구사항

## 1. 타겟
경제 뉴스를 읽지만 어려운 용어나 현상 때문에 기사의 맥락과 의미까지 이해하기 어려운 사용자

## 2. 문제
기사에 등장하는 개념의 뜻은 검색할 수 있지만, 왜 이 기사에서 중요한지, 어떤 영향을 만드는지까지 연결해 이해하기 어렵고, 읽은 내용이 자신의 지식으로 남기 어려움.

## 3. 핵심 솔루션
경제 뉴스 본문을 붙여넣으면 AI가 기사를 이해하는 데 꼭 필요한 학습 포인트를 최대 3개까지 선별한다. 각 포인트를 **개념 정의 → 쉬운 설명 → 기사 속 맥락 → 경제적 영향** 순서로 학습하고, 학습한 개념을 바탕으로 기사 전체 흐름을 다시 3문단으로 요약해서 보여준다(뉴스 다시 이해하기). 이어서 이해도를 확인하는 OX 퀴즈를 필수로 풀고, 마지막으로 선택적으로 사용자가 직접 자신의 언어로 기사를 정리한다.

포인트 개수를 최대 3개로 제한하는 것은 두 가지 이유다: (1) 서비스의 핵심 가치가 "전체 요약"이 아닌 "이해에 꼭 필요한 것만 선별"하는 데 있어, 개수가 늘어날수록 일반 요약 서비스와의 차별성이 흐려지고 (2) 한 번에 소화 가능한 개념 수를 넘기면 학습 피로도가 높아져 학습 효과가 떨어지기 때문이다.

## 4. AI 역할
- 기사 전체를 단순 요약하지 않고, **학습할 가치가 있는 핵심 개념·현상을 최대 3개까지 선별**
- 선별한 개념의 정의, 쉬운 설명, 기사 속 맥락, 경제적 영향을 연결해 설명
- 학습된 핵심 개념을 바탕으로 기사 전체 사건의 흐름을 3문단으로 재구성(이미 배운 개념 정의를 반복하지 않고, 사건 전개에 집중)
- 핵심 포인트 개수와 동일한 수의 OX 문제를 생성하고, 각 문제는 정답 여부와 해설을 제공

## 5. 사용 흐름
```
시작 화면 (로고 + 서비스명 + 슬로건)
   ↓
닉네임 입력 (필수 — 미입력 시 진행 불가)
   ↓
경제 뉴스 본문 붙여넣기 (최대 10,000자)
   ↓
AI 핵심 포인트 최대 3개 선정
   ↓
포인트별 학습: 개념 정의 → 쉽게 말하면 → 이 기사에서는 → 그래서 어떤 영향?
   ↓
뉴스 다시 이해하기 — 학습한 개념 기반, 기사 전체 흐름 3문단 요약
   ↓
OX 퀴즈 (필수, 문항 수 = 핵심 포인트 개수) → 응시 후 일괄 정답/해설 확인
   ↓
내 말로 정리하기 (선택 — "필수 아님" 안내 문구 표시)
   ↓
학습 완료 축하 화면
   ↓
마이페이지 저장 (기사 제목/날짜/포인트 수/퀴즈 점수/정리 내용, localStorage 영구 보관)
```

## 6. 동작 요건 (기능 명세)

### 온보딩
1. 사용자가 서비스에 처음 접속하면 시작 화면(로고, 서비스명, 슬로건)을 본다.
2. "시작하기"를 누르면, localStorage에 저장된 닉네임이 있으면 바로 홈으로, 없으면 닉네임 입력 화면으로 이동한다.
3. 닉네임 입력은 필수이며, 빈 값이나 공백만 입력 시 진행할 수 없고 경고 문구가 표시된다.
4. 닉네임 없이 홈 화면에 직접 접근을 시도하면 시작 화면으로 리다이렉트된다.

### 핵심 포인트 학습
5. 사용자가 경제 뉴스 본문을 붙여넣으면(최대 10,000자), 시스템은 AI를 호출해 기사 제목과 핵심 학습 포인트를 최대 3개까지 선정한다.
6. 각 포인트는 "개념 정의", "쉽게 말하면(초등학생도 이해 가능한 수준)", "이 기사에서는(맥락)", "그래서 어떤 영향?(경제적 영향)" 4단 구조로 표시된다.
7. AI 응답이 3개를 초과하는 포인트를 반환할 경우, 코드 레벨에서 상위 3개만 사용하도록 잘라낸다(안전장치).
8. 사용자는 포인트를 순서대로 하나씩 넘겨가며 학습한다 (예: 1/3, 2/3 진행 표시).

### 뉴스 다시 이해하기
9. 핵심 포인트 학습을 마치면, 학습한 개념을 바탕으로 기사 전체 사건 흐름을 3문단으로 요약해 보여준다.
10. 이 요약은 개념 정의를 반복하지 않고 "무슨 일이 일어났는지 → 배경/경위 → 의미와 시사점" 순서로 구성된다.
11. 요약 하단에 "본 요약에는 글을 작성한 기자의 해석 또는 의견이 포함될 수 있습니다"라는 면책 문구를 표시한다.

### 퀴즈 (필수)
12. 핵심 포인트 개수와 동일한 수의 OX 문제를 생성한다 (포인트 1개면 1문항, 3개면 3문항).
13. 각 문제는 대응하는 핵심 포인트 하나와 연결된다.
14. 사용자가 모든 문제에 응답해야 "정답보기" 버튼이 활성화된다.
15. "정답보기"를 누르면 전 문항의 정답 여부와 해설, 맞은 개수 요약을 한 번에 표시한다.
16. 퀴즈는 건너뛸 수 없다 (필수 단계).

### 정리하기 (선택)
17. 퀴즈 완료 후, 화면 상단에 "이 단계는 필수가 아니에요" 안내 문구와 함께 정리 입력 화면으로 이동한다.
18. 사용자가 기사를 자신의 언어로 정리할 수 있는 입력창이 제공되며, 힌트로 핵심 개념 기반 키워드 칩을 함께 보여준다.
19. 정리를 작성하거나 건너뛰고 "학습 완료"를 누르면 학습 완료 축하 화면으로 이동한다.

### 저장 및 마이페이지
20. 학습 완료 시점에 기사 제목, 학습 날짜, 핵심 포인트 개수, 퀴즈 점수, 정리 내용(있는 경우)을 localStorage에 영구 저장한다.
21. 마이페이지는 누적 통계(직접 정리한 뉴스 수, 이해한 핵심 포인트 수, 이번 주 학습 수, 연속 학습일)와 최근 학습 목록을 표시하며, 사이드바/상단에 닉네임을 노출한다.
22. 신규 사용자(저장된 기록 없음)에게는 통계 0과 "아직 학습 기록이 없어요" 안내를 보여준다.
23. "학습 기록 초기화" 버튼으로 학습 기록/통계만 삭제할 수 있으며, 닉네임은 유지된다.
24. 현재 학습 중인 기사 본문 등 페이지 간 임시 전달 데이터는 sessionStorage를 사용해 새 학습 시작 시 초기화된다.

## 7. 화면 구성
1. **시작 화면 (splash)**: 로고 + 서비스명 + 슬로건, "시작하기" 버튼
2. **닉네임 입력 (nickname)**: 닉네임 입력창, 필수 검증
3. **홈 (index)**: 기사 본문 붙여넣기 + 최근 학습 목록 (빈 상태 처리 포함)
4. **핵심 포인트 학습 (lesson)**: 포인트별 4단 설명 카드, N/M 진행 표시
5. **뉴스 다시 이해하기 (overview)**: 3문단 요약 카드, 면책 문구
6. **퀴즈 (quiz)**: OX 문제 카드(포인트 개수만큼), 일괄 정답/해설 확인
7. **정리하기 (summary)**: 자유 서술 입력창 + 키워드 힌트 칩, "선택 단계" 안내
8. **학습 완료 (complete)**: 축하 연출, 연속 학습일 강조
9. **마이페이지 (mypage)**: 닉네임 노출, 누적 통계 카드, 최근 학습 목록, 기록 초기화 버튼

## 8. 차별성 (경쟁 서비스 대비)

| 기능 | 뉴닉/어피티 | 범용 요약 AI(NewsDigest 등) | 경제용어 퀴즈(생글생글 등) | 뉴스레슨 |
|---|---|---|---|---|
| 사용자가 원하는 기사 자유 입력 | ❌ (자체 콘텐츠만) | ✅ | ❌ | ✅ |
| 핵심 개념 선별(전체 아닌 최대 3개) | ❌ | ❌ (전체 요약) | - | ✅ |
| 정의→맥락→영향 단계적 설명 | ❌ | ❌ | ❌ | ✅ |
| 학습 후 사건 흐름 재요약 | ❌ | ❌ | ❌ | ✅ |
| 확인 퀴즈 | ✅ (독립형) | ❌ | ✅ (독립형) | ✅ (핵심 포인트 개수에 연동) |
| 사용자가 직접 정리(산출) | ❌ | ❌ | ❌ | ✅ (핵심 차별점) |

**핵심 메시지**: 기존 서비스들은 요약 또는 퀴즈 중 한 기능에 머물러 있고, 이해 → 정리로 이어지는 학습 흐름은 제공하지 않는다.

## 9. 완성도 우선순위 (MVP 스코프)

**필수 (Must-have)** — 전부 구현 완료
- 온보딩(시작 화면, 닉네임 필수 입력)
- 기사 붙여넣기 → 핵심 포인트 최대 3개 선정 → 4단 설명 표시
- 뉴스 다시 이해하기 (3문단 재요약)
- OX 퀴즈 (필수, 포인트 개수만큼)
- 마이페이지 기본 목록/통계, localStorage 영구 저장

**선택 (Nice-to-have)** — 구현 완료
- 사용자 정리 입력 (퀴즈 이후 선택 단계)
- 키워드 힌트 칩 자동 생성
- 학습 완료 축하 화면

## 10. 기술 스택
- 프론트엔드: HTML/CSS/Vanilla JS (프레임워크 없이 경량 구현)
- AI 처리: Google Gemini API
- 데이터 저장: localStorage(영구 기록) + sessionStorage(페이지 간 임시 전달)
- 출력 형식: JSON 구조로 강제하여 프론트 렌더링 안정성 확보
- 개발 도구: Claude Code

## 11. 발표 포인트
- "요약이 아니라 선별", "압축이 아니라 압축 해제"라는 프레이밍 유지
- 핵심 포인트를 최대 3개로 제한한 이유: 서비스 차별성 유지 + 학습 피로도 관리
- 인출 학습(retrieval practice) 원리와 연결해 "직접 정리"의 학습 효과 근거 제시
- 퀴즈는 부가 기능이 아니라 학습 직후 이해도를 즉시 확인하는 필수 관문으로 포지셔닝
- 로그인 없이 닉네임 + localStorage만으로 개인화 경험을 제공한 이유(비용·시간 효율)를 확장 로드맵과 함께 설명 가능
